# Explicit Limitations & Scope Disclosures

Transparency over what runs natively today vs. what requires a Docker/Kubernetes host:

1. **Host Runtime Environment (`local_native`):** The development workstation used to verify tests and benchmarks runs macOS ARM64 (`Darwin 24.6.0`, Apple M4 Pro) without Docker, Podman, a host JVM, or a standalone `opa` CLI binary. Consequently:
   - The `local_native` profile executes real **Apache Iceberg V2** (`pyiceberg` SQLite catalog + ZSTD Parquet), **DuckDB**, **Avro v1/v2** (`fastavro`), **OpenTelemetry SDK**, **Prometheus**, and **FastAPI** natively.
   - Multi-container distributed profiles (`docker-compose.yml` with Kafka, Apicurio, RustFS, Lakekeeper, Spark 4.1, Airflow 3.4, Marquez, OPA 1.22.3, Prometheus, Loki, Grafana) and `docker-compose.standalone.yml` are fully authored with pinned versions and validated in CI, but were not live-booted on this Docker-free workstation.
2. **Embedded OPA Parity Engine vs. Remote OPA Server:** When `OPA_POLICY_URL` is unset (default in `local_native`), `agentic_sre/opa_policy.py` evaluates the exact rule set defined in `infra/opa/remediation_policy.rego`. When `OPA_POLICY_URL` points to `openpolicyagent/opa:1.22.3` in Docker/Kubernetes, requests dispatch directly to OPA's REST API, and GitHub Actions CI runs native `opa test` against `infra/opa/remediation_policy_test.rego`.
3. **Lineage Ingestion Scope:** OpenLineage edges are loaded from explicit RunEvent JSON contracts (`schemas/openlineage/platform_lineage_events.json`) and persisted into `silver.asset_lineage_graph`. Automatic SQL AST parsing or runtime Spark/Airflow listener emission is only active when running the distributed `analytics` profile with Marquez (`marquezproject/marquez:0.51.1`, which requires `linux/amd64` emulation on ARM64).
4. **Optional Local LLM Narration:** `OptionalLocalLLMAdapter` is disabled by default (`ENABLE_LOCAL_LLM=false`) and zero pretrained model weights are downloaded or evaluated in local tests/benchmarks.
5. **Simulated Fixture Platform State:** Remediation tools (`rollback_config_version`, `bounded_retry_task`, `backfill_partition`, `pause_broken_pipeline`, `rebuild_materialized_view`) mutate a durable fixture state store persisted alongside Iceberg V2 snapshots rather than issuing live AWS/GCP/Airflow REST calls; swapping in real Airflow/Iceberg REST executors requires implementing the same typed allowlisted adapter methods.
6. **MTTR Benchmark Methodology:** Manual triage MTTR values (18–45 minutes depending on scenario) are documented baseline estimates, while policy-approved self-healing MTTR sums measured sub-second correlation/RCA runtime + a fixed 60-second human approval review budget + 2.5-second execution/verification time.
